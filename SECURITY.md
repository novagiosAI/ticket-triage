# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| 0.1.x | ✅ |

## Reporting a vulnerability

**Please do not open a public GitHub issue for security problems.**

- GitHub → **Security** tab → *Report a vulnerability*, or
- email **security@novagios.com**

We aim to acknowledge within 5 business days and to ship a fix or give a timeline
within 30 days.

## The model contains no customer data

Every training example is generated by
[`glpi-testkit`](https://github.com/novagiosAI/glpi-testkit) from templates committed
in plain sight. There is no source dataset, so the published artifact cannot leak
one. A model trained on real tickets can memorise and regurgitate them; this one has
nothing to memorise.

If you retrain on **your own** tickets, that guarantee becomes yours to maintain:

- The artifact then encodes your data. Treat `model.joblib` as confidential and do
  not publish it.
- Strip identifiers before training —
  [`glpi-anonymizer`](https://github.com/novagiosAI/glpi-anonymizer) or
  [`presidio-mena`](https://github.com/novagiosAI/presidio-mena).
- Under GDPR and Moroccan law 09-08, a model trained on personal data is still
  processing personal data.

## Loading a model is loading code

`TicketTriageModel.load()` uses `joblib`, which uses `pickle`. **Unpickling runs
arbitrary code.** Only load artifacts you produced yourself or obtained from a
source you trust — never one a user uploaded. The `ARTIFACT_VERSION` check is a
compatibility guard, not a security boundary.

If you expose retraining or model upload to untrusted users, that is the risk to
design around, and the one we would most want reported.

## Deploying the demo

`app.py` accepts arbitrary text and runs inference on it. It writes nothing, calls
nothing external, and holds no secrets. Standard web hygiene applies — rate limiting
above all, since inference is the expensive part.
